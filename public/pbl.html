1 — High-Level Summary

Bharat Health Pass (BHP) is an AI-driven digital wallet that centralizes health data and streamlines hospital interactions through intelligent processing.

"Centralized health data + AI understanding + QR-based identity."

BHP eliminates documentation friction: Mobile Upload → ML Kit OCR → Groq LLM Intelligence → Secure Firestore → Hospital QR Scan.

2 — Core Design Decisions

Kotlin & Jetpack Compose

Built for performance and modern UX on Android with a clean, reactive UI architecture.

AI Processing Layer

Groq API for fast LLM inference combined with on-device ML Kit for secure OCR extraction.

Firebase Backend

Full integration with Auth, Firestore, and Storage for scalable, real-time health data management.

4 — End-to-End Workflow

01

Authentication

  • Seamless Google + Email onboarding via Firebase Auth.
  • Zero-knowledge user profiling for personalized health views.
  • Biometric device binding for high-security health data access.
02

Record Upload

  • Upload prescriptions, lab reports, or insurance docs.
  • Secure storage in Firebase with granular access control.
  • Instant indexing for immediate AI-driven health insights.
03

AI Processing

  • On-device ML Kit extracts critical text and data fields.
  • Groq AI transforms raw medical jargon into simple insights.
  • Automated flagging of trends and pre-visit report generation.
04

Health Pass + Hospital

  • Instant QR scan enables secure record sharing with providers.
  • hospital mode allows doctors to view full AIed summaries.
  • Secure audit logs track every access and treatment event.

8 — Claims Automation

ML Kit OCR

On-device text recognition pipeline for rapid, private data extraction from images. Handles various medical document layouts with high accuracy.

Groq AI Layer

Leverages Groq's high-speed inference for real-time LLM processing. Simplifies medical jargon into patient-friendly summaries instantly.

Data Structuring

Transforms unstructured OCR output into clean, queryable Firestore documents. Ensures data consistency across the entire ecosystem.

11 — Security & Privacy

  • • Biometric Lock: App access secured via fingerprint/face unlock.
  • • AES-256 Encryption: All health records encrypted at rest & in transit.
  • • Identity Masking: No raw biometric or PII data stored in clear text.
  • • Signed Logs: Audit trails of every document access and scan.

10 — Legal

Compliance with Digital Personal Data Protection (DPDP) Act. Patient consent is central.

Records stored with end-to-end encryption, ensuring only authorized providers see data.

User retains full ownership and control over data sharing permissions.
